# Architecting-LR1

Теория:
Контейнеризация — технология упаковки приложения вместе с его зависимостями, настройками и окружением в изолированную среду. Это позволяет запускать приложение одинаково на разных компьютерах и серверах.
Контейнер — запущенный экземпляр образа. Он содержит приложение, его зависимости и настройки, но работает изолированно от других процессов и контейнеров.
Образ (image) — неизменяемый шаблон, из которого создаётся контейнер. В нём находятся код приложения, зависимости, системные файлы и команда запуска.

Упаковать java-приложение из примера в докер через команду
```docker build ./ -t "java_app"```
Проверить список образов образ командой:
```docker images -a```
Создать контейнера из образа:
```docker run -d -p 8080:8080 java_app```
Однако контейнер не запуститься так как приложению требуется postgres компаньон для работы.
Запушить образ контейнера на dockerhub:
```docker push deazible/bivt-23-sp2_bordackov-ms```
Проверить на веб странице по адресу:
```https://hub.docker.com/repository/docker/deazible/bivt-23-sp2_bordackov-ms/general```
Запустить приложение из папки compose (-d для тихого/фонового запуска):
```docker compose up -d```
Для входа в терминал контейнера:
```docker exec -it architecturing_lr1-postgres-1 bash```
